# Flutter UI/UX Skills — دليل الاستخدام

حزمة من 11 مهارة تساعد المساعد البرمجي على تصميم واجهات Flutter وتطويرها
ومراجعتها وتحسينها. تثبّت المهارات داخل مشروع تطبيقك، ثم تطلب من المساعد
استخدامها في المحادثة. محتوى الحزمة تعليمات Markdown، ولا تحتاج لإضافتها
كاعتمادية Dart داخل `pubspec.yaml`.

[English README](README.md) · [قائمة المهارات](README.md#choose-a-skill)

## النسخة الحالية

النسخة **0.2.0rc1** مرشّح إصدار. الحزمة الكاملة موجودة في الفرع
[`fix/flutter-ui-ux-activation-reliability`](https://github.com/sayedsaad96/flutter-ui-ux-skills/tree/fix/flutter-ui-ux-activation-reliability).
الأوامر التالية تختار هذا الفرع صراحةً؛ قد يحتوي الفرع الرئيسي على النسخة
القديمة ذات المهارة الواحدة. لا نفترض وجود إصدار مستقر منشور.

## 1. جهّز المتطلبات

- Node.js بإصدار **22.20.0 أو أحدث**، مع npm وnpx.
- Git متاح من الطرفية.
- مساعد برمجي يدعم Agent Skills. الأمثلة التالية تستخدم Codex.
- مشروع Flutter وFlutter SDK للعمل على التطبيق والتحقق منه.

افتح الطرفية وتأكد من الأدوات:

```bash
node --version
npm --version
git --version
flutter doctor
```

يمكن تثبيت الأدوات من [Node.js](https://nodejs.org/en/download)
و[Git](https://git-scm.com/downloads)
و[دليل إعداد Flutter](https://docs.flutter.dev/get-started/install).
عالج مشكلات إعداد Flutter المتعلقة بالمنصة التي ستختبر عليها.

## 2. ثبّت الحزمة داخل تطبيقك

افتح الطرفية في **المجلد الرئيسي لتطبيق Flutter الذي تريد العمل عليه**،
حيث يوجد ملف `pubspec.yaml`، ثم نفّذ:

```bash
npx skills@1.7.4 add "sayedsaad96/flutter-ui-ux-skills#fix/flutter-ui-ux-activation-reliability" --skill "*" --agent codex --copy --yes
```

قد يطلب npm في المرة الأولى الموافقة على تنزيل أداة التثبيت. الأمر يثبّت
المهارات الـ11 في المشروع الحالي ويستهدف Codex، ويستخدم النسخ المباشر لتجنّب
مشكلات الروابط على Windows. لا يثبّتها على مستوى الجهاز لأننا لم نستخدم الخيار
العام. إصدار أداة التثبيت المثبّت في الأمثلة هو `1.7.4` الذي اختُبر مع الحزمة.

في Codex ستجد 11 مجلدًا داخل `.agents/skills/`، ولكل مهارة ملف `SKILL.md`.
قد تُنشئ الأداة ملف `skills-lock.json` أو تحدّثه؛ يمكن حفظه مع المشروع لتسجيل
مصادر المهارات المثبتة.

لاستخدام مساعد آخر، استبدل `--agent codex` بأحد الخيارات المناسبة:

| المساعد | المعرّف |
|---|---|
| Codex | `codex` |
| Claude Code | `claude-code` |
| Cursor | `cursor` |
| Antigravity | `antigravity` |

توضح [قائمة المساعدين المدعومين](https://github.com/vercel-labs/skills/blob/main/docs/agents.md)
المعرّفات ومسارات التثبيت. اختبارات سلوك هذه النسخة أُجريت في Codex؛ يحتاج
أي مساعد آخر إلى التحقق في بيئته، ويمكن استدعاء المهارة صراحةً عندما لا يختارها
تلقائيًا.

لتثبيت المهارة الأساسية وحدها، استخدم:

```bash
npx skills@1.7.4 add "sayedsaad96/flutter-ui-ux-skills#fix/flutter-ui-ux-activation-reliability" --skill flutter-ui-ux --agent codex --copy --yes
```

تعمل المهارة الأساسية وحدها وتنفّذ التفكير المطلوب مباشرةً عند غياب مهارة
متخصصة. تثبيت الحزمة كاملة يوفّر الإرشادات المتخصصة كلها.

## 3. تأكد من نجاح التثبيت

من مجلد تطبيقك نفسه، نفّذ:

```bash
npx skills@1.7.4 list --agent codex
```

بعد التثبيت الكامل، يفترض ظهور أسماء المهارات الـ11 الموجودة في
[جدول المهارات](README.md#choose-a-skill). افتح المساعد على مشروع التطبيق
وابدأ محادثة أو جلسة جديدة ليتعرّف على المهارات المضافة.

## 4. استخدم المهارات في المحادثة

انسخ الأمثلة التالية إلى **محادثة المساعد، وليس إلى الطرفية**. الرمز `$` يحدد
المهارة بالاسم في Codex. في المساعدين الآخرين، استخدم قائمة المهارات أو اطلب
صراحةً قراءة ملف `SKILL.md` الخاص بالمهارة المثبتة قبل تنفيذ الطلب.

لأغلب مهام واجهات Flutter ابدأ بالمهارة الأساسية:

```text
$flutter-ui-ux راجع واجهات الدفع في lib/features/checkout، ثم أصلح المشكلات
المهمة. افحص الكود الحالي أولًا، وحافظ على إدارة الحالة والتنقل الموجودة.
اشرح ما غيّرته وما تحققت منه فعليًا.
```

استبدل المسار بمسار حقيقي داخل تطبيقك، وامنح المساعد إمكانية الوصول للمشروع.
أرفق صور الشاشات أو وفّر تشغيل التطبيق عندما تريد التحقق من المظهر والتفاعل.

أمثلة لمهام محددة:

```text
$creating-flutter-ui أنشئ شاشة لإضافة المصروفات باستخدام ثيم التطبيق الحالي.
ادعم العربية والإنجليزية، وحالات التحميل والتحقق من الإدخال والخطأ.
```

```text
$auditing-flutter-ui راجع تجربة التسجيل واعرض المشكلات مرتبة حسب الأولوية،
مع الأدلة والتوصيات فقط. لا تعدّل أي ملفات.
```

```text
$designing-inclusive-flutter أصلح تجاوز النص الكبير ومزج العربية والإنجليزية
في صف الفاتورة، مع الحفاظ على البيانات الأصلية والاستدعاءات الحالية.
```

```text
$crafting-flutter-motion حسّن تفاعل حفظ العلامة في شاشة القراءة، مع الحفاظ
على موضع القراءة وحالة الصوت واحترام إعداد تقليل الحركة.
```

```text
$verifying-flutter-ui تحقّق من الشاشات المعدّلة قبل النشر. افصل نتائج فحص
الكود والتشغيل والمظهر وإمكانية الوصول والمنصات، واذكر ما لم تتمكن من اختباره.
```

المهارة الأساسية تصنّف المهمة وتوضح الأدلة المتاحة وتختار القدر اللازم من
الإرشادات. يجب أن تصرّح بغياب الكود أو الصور أو التشغيل، وأن تميّز ما تحققت
منه عمّا بقي دون تحقق. طلب المراجعة فقط يبقى دون تعديل للملفات.

## اختيار المهارة المناسبة

| المهارة | الاستخدام |
|---|---|
| `flutter-ui-ux` | تنسيق المهمة واختيار المسار والمهارات المناسبة |
| `creating-flutter-ui` | إنشاء شاشات أو مكونات أو تدفقات جديدة |
| `redesigning-flutter-ui` | تحسين واجهة موجودة بعد فحصها |
| `auditing-flutter-ui` | مراجعة المشكلات والأولويات دون تعديل |
| `designing-flutter-systems` | الثيم والألوان والخطوط والرموز التصميمية |
| `building-responsive-adaptive-flutter` | أحجام الشاشات وتغيير المساحة وطرق الإدخال |
| `engineering-flutter-ui` | تركيب Widgets وعرض الحالات وأداء الواجهة |
| `designing-inclusive-flutter` | إمكانية الوصول والتعريب وRTL والنص الكبير والتركيز |
| `crafting-flutter-motion` | الحركات الهادفة ودورة حياتها وتقليل الحركة |
| `polishing-flutter-experiences` | التسلسل البصري والمحاذاة والمسافات والصقل |
| `verifying-flutter-ui` | فحص الجودة والأدلة وحدود الجاهزية |

يمكن استخدام كل مهارة بمفردها. تنطلق الإرشادات من هوية المنتج وبنية التطبيق
الحالية، وتختار ما تحتاجه المهمة بدل فرض نمط بصري أو معمارية واحدة.

## التحديث والإزالة

لتحديث الحزمة كاملة من الفرع نفسه، أعد تشغيل أمر التثبيت الكامل داخل المشروع.
راجع أي تعديلات محلية على النسخ المثبتة أولًا؛ فقد تستبدلها إعادة التثبيت.

لإزالة المهارة الأساسية وحدها:

```bash
npx skills@1.7.4 remove flutter-ui-ux --agent codex --yes
```

لإزالة عدة مهارات، شغّل `npx skills@1.7.4 remove` واختر أسماء هذه الحزمة من
القائمة التفاعلية. تجنّب `--all` إذا كان المشروع يحتوي مهارات من مصادر أخرى.

## التثبيت من نسخة محلية

يمكن تنزيل الفرع إلى جهازك أولًا:

```bash
git clone --branch fix/flutter-ui-ux-activation-reliability --single-branch https://github.com/sayedsaad96/flutter-ui-ux-skills.git
```

عُد إلى مجلد تطبيق Flutter المستهدف، ثم نفّذ الأمر التالي بعد استبدال المسار
بالمسار الكامل لمجلد `skills` في النسخة التي نزّلتها:

```bash
npx skills@1.7.4 add "/absolute/path/to/flutter-ui-ux-skills/skills" --skill "*" --agent codex --copy --yes
```

على Windows قد يكون المسار مثل `C:/Projects/flutter-ui-ux-skills/skills`.
اتركه بين علامتي اقتباس إذا احتوى مسافات. يتطلب هذا الخيار وجود أداة التثبيت
أو نسختها المخزنة محليًا؛ تنزيل مصدر المهارات وحده لا يوفّر كل متطلبات العمل
دون اتصال.

## معالجة المشكلات الشائعة

| المشكلة | الإجراء |
|---|---|
| الأمر `npx` غير معروف | ثبّت Node.js بالإصدار المطلوب، ثم افتح الطرفية مجددًا. |
| تظهر مهارة واحدة أو أقل من 11 | استخدم الأمر الكامل مع الفرع `#fix/...` والخيار `--skill "*"`. |
| المساعد لا يرى المهارات | تأكد من مجلد التطبيق والمساعد المستهدف، ثم ابدأ محادثة جديدة. |
| المساعد لا يطبق التعليمات | استدعِ `$flutter-ui-ux` أو المهارة المطلوبة بالاسم. |
| يفشل الوصول إلى GitHub | افحص الاتصال وGit، أو استخدم خيار النسخة المحلية. |
| تفشل الروابط على Windows | استخدم الخيار `--copy` كما في الأمثلة. |
| المراجعة تبدأ بتعديل الملفات | استخدم `auditing-flutter-ui` واذكر أنك تريد النتائج فقط. |
| التحقق من المظهر أو الأجهزة غير ممكن | وفّر التطبيق أو الصور أو التشغيل، واطلب ذكر الجوانب غير المختبرة. |

## ما تم اختباره وحدود النتائج

اجتاز المرشّح 24 اختبار Python، و6 سيناريوهات للمهارة الأساسية، و10 سيناريوهات
تطبيق للمهارات الأخرى. أُجريت أيضًا أربع تجارب اكتشاف في Codex وتثبيت معزول
للمهارات الـ11. بعض الاختبارات نجحت قبل إضافة المهارات؛ لا ندّعي تحسنًا مقاسًا
في تلك الحالات. التفاصيل في [حالة التقييم](evals/STATUS.md)
و[تقرير الجاهزية](docs/RELEASE_READINESS.md).

هذه النتائج تخص الإرشادات وتثبيتها، ولا تمنح تطبيقك اعتمادًا تلقائيًا على
الأجهزة أو قارئات الشاشة أو الأداء. تحقّق من التطبيق الذي تعدّله، ولا تفترض
أن الاكتشاف التلقائي أو السلوك متماثل في جميع المساعدين.

للمساهمين: توجد أوامر التحقق ومتطلبات Python في
[README الإنجليزي](README.md#validation-and-limits) و[دليل المساهمة](CONTRIBUTING.md).
المستخدم العادي للمهارات لا يحتاج Python.
