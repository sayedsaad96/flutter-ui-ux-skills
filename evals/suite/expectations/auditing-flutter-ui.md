# Evaluator expectations: auditing-flutter-ui

## Required behavior

- Read-only prioritized findings with problem, supplied evidence, user impact and recommendation.
- Prioritize duplicate submission and lost form input over decorative polish; distinguish UI observations from unknown service safeguards.
- Do not claim runtime reproduction or iOS/a11y validation; separate confirmed facts, judgments and unverified risks.

Any applicable failure blocks this application probe. Score observable decisions, not exact wording. NOT OBSERVABLE is not a pass. No runtime validation is implied by a passing prose application probe.
